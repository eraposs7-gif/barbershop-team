Сайт барбершопа. Новую страницу делаем в ветке,
отправляем на GitHub и вливаем через Pull Request —
так работают в командах: никто не пишет прямо в main.
Терминал — в папке homework. Вместо <логин> — ваш логин.
Шпаргалка — SUMMARY.md рядом.

── ШАГ 1 · ОСНОВА НА GITHUB ──
Что: init, .gitignore со строкой SUMMARY.md, add .,
     commit «Сайт барбершопа». Пустой репозиторий
     barbershop-team на GitHub, remote add origin,
     push -u origin main. Состояние ветки (status -sb).
Проверьте: git status -sb печатает ## main...origin/main,
           на GitHub видны ваши файлы.

── ШАГ 2 · ВЕТКА СО СТРАНИЦЕЙ ──
Что: ветка feature/contacts (switch -c). Создайте
     contacts.html — каркас документа и h1 «Контакты».
     add, commit «Страница контактов».
     Отправьте ветку: git push -u origin feature/contacts.
     Ветки на GitHub: git branch -r
Проверьте: git branch -r показывает 2 ветки на GitHub:
           origin/feature/contacts
           origin/main

── ШАГ 3 · PULL REQUEST ──
Что: на GitHub появится кнопка Compare & pull request.
     Откройте PR: заголовок «Страница контактов»,
     в описании — что сделано. Create pull request →
     Merge pull request → Confirm merge.
Итог: на GitHub в main есть contacts.html.

── ШАГ 4 · ЗАБРАТЬ СЛИТОЕ ──
Что: у себя: switch main, git pull. Файл на месте:
     ls contacts.html
Проверьте: в main после pull ls contacts.html печатает
           contacts.html — страница пришла.

── ШАГ 5 · УБРАТЬ ВЕТКУ ──
Что: удалите ветку у себя (branch -d feature/contacts)
     и на GitHub: git push origin --delete feature/contacts.
     Ветки на GitHub (branch -r).
Проверьте: git branch -r показывает одну ветку:
           origin/main

── ВОПРОСЫ (ответьте письменно здесь, в этом файле) ──
1) Зачем работать в отдельной ветке, а не сразу в main?
2) Что такое Pull Request и зачем в нём ревью?
3) Почему возникает конфликт и как его решить?
   Что значат <<<<<<<, ======= и >>>>>>>?

Ответы:
1) Отдельная ветка позволяет разрабатывать новую функцию, не затрагивая стабильную ветку `main`. Изменения можно проверять и обсуждать до объединения.
2) Pull Request (PR) — предложение включить изменения из одной ветки в другую. Ревью помогает заметить ошибки, обсудить решение и проверить код перед слиянием.
3) Конфликт возникает, когда в двух ветках по-разному изменили один и тот же участок файла и Git не может выбрать итог самостоятельно. Нужно открыть конфликтующий файл, сравнить варианты, оставить правильный итоговый текст, удалить маркеры, затем выполнить `git add` и завершить слияние коммитом. `<<<<<<<` обозначает начало первого варианта, `=======` разделяет варианты, `>>>>>>>` завершает второй вариант.
